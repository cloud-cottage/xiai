# 规范增量 v1.123 —— 印面 ID 改 8 位字母（base-22）＋ 首页数字 OTP 改 9 位印人检索

- 作者：Zang（本轮破例）
- 提出：Kevin（2026-11-15）
- 裁定（clarify 四答）：① 沿用 seal 的 22 字母表（零新增字母表）；② 全量重编、旧码作废；
  ③ fid 仍由 `face_no` 派生；④ 9 位纯数字 ＝ CARD 人物号，命中即跳 `/persons/<号>`
- 主件状态：**未动** `docs/xiai.spec.md`（v1.117 / 794 条），由 Jing 合并；接 v1.122（`AC-815〜819`）

## 一 · 印面标识 `fid`（口径变更）

| 项 | 旧 | 新 |
|---|---|---|
| 形态 | 十进制 8 位零填充 `00001399` | **8 位 base-22 展开** `AAAAAAAB` |
| 字母表 | — | 与 `sid` **同一张 22 字母表** `ABCDEFGHJKMNPQRSTVWXYZ`（不含 I / L / O / U） |
| 高位填充 | `0` | `A` |
| 已知向量 | `1 → 00000001` | `1 → AAAAAAAB`、`22 → AAAAAABA`、`22⁸−1 → ZZZZZZZZ` |
| 码空间 | `10⁸` | `22⁸ = 54,875,873,536`（号域 `[1, 54,875,873,535]`） |
| 派生源 | `face_no` | **仍为 `face_no`**（不另立号域） |

- `codeId.js` **三副本**（`src/utils` / `xiai-user-token/lib` / `xiai-admin-token/lib`）必须逐字节相同
  （`verify-code-id` C1a/C1b 机械 cmp）。
- **数据迁移**：全库 6,524 个印面 `fid` 全量重写（0 失败、0 残留旧形态）；**旧 8 位数字一律作废**，
  不保留兼容映射（Kevin 裁定）。
- 编码分型改按**长度**：5 位字母 ⇒ `sid`（印章）、8 位字母 ⇒ `fid`（印面）。
  **判负面**：仍按首字符是否数字分型、或保留十进制 fid 兼容分支。

## 二 · 首页搜索框（数字态语义变更）

- 数字 OTP **8 格 → 9 格**；填满或粘贴 9 位数字即跳 `/persons/<9 位>`（CARD 人物号，如 `100000159`）。
- 字母 OTP（5 格｜印章码）不变；面码不再是搜索入口（8 字母码可由 `?code=` 精查）。
- 不存在的印人号**不在页头拦截**：详情页按 CARD 主库查询、查无明示「查無此人」。
- 粘贴校验文案随之改为「9 位純數字印人號」。

## 三 · 验收（`AC-820` 〜 `AC-824`）

| 编号 | 判据 |
|---|---|
| `AC-820` | `encodeFaceCode` 为 8 位 base-22：`1 → AAAAAAAB`、`22 → AAAAAABA`、`FID_LAST → ZZZZZZZZ`；`FID_MAX ＝ 22⁸` |
| `AC-821` | `codeId.js` 三副本逐字节相同；字母表与 `sid` 同源（仅 22 字母，无 I/L/O/U） |
| `AC-822` | 解码形态门只认 8 位字母；数字串 / 7 位 / 9 位 / 含 I·L·O·U ⇒ `INVALID_VALUE` |
| `AC-823` | 全库印面 `fid` ＝ `encodeFaceCode(face_no)`（无一行残留旧十进制形态） |
| `AC-824` | 首页数字 OTP 恰 9 格；填满 9 位数字跳 `/persons/:code`；**判负面**：仍走 `?code=` 印章精确查 |
