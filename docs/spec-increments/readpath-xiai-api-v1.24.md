#### 3.24.1 架构定案与两面职责（写入面 ＝ feicui-lite；读取面 ＝ xiai-api）

- **定案（Kevin 2026-09-23 逐字三条，见 §2.1 原文 44）**：**① 写入面** —— **「用户上传图片的时候，经由 feicui-lite 模块（feicui 是本地运行，feicui-lite 是在线运行）把图片转换格式，face-photo 使用 tiff，scene-photo 使用 avif。管理员可以使用 feicui 去解析 pdf 文件大批量得到图片素材，素材的格式同样也是 face→tiff、scene→avif。上述部分不涉及到资源的防泄露，所以尽可能都在前端进行。」**；**② 读取面** —— **「用户在前端访问图片的时候，当用户预览时后台分别将 tiff 和 avif 转换为 webp 然后经过 TileSplicer，最终通过 api 输出给前端。如果是缩略图或者是用户正在下载这个资源（文案叫做：下载高清原图）那么不经由 TileSplicer，直接通过 api 输出给前端。」**；**③ api 命名与消费面** —— **「上述这套 API 我们称之为 xiai-api。除了为 xiai 的 web 页面提供内容，同时它也是 yinsuo 的内容数据的提供者。」**
- **⇒ 明文六条（可机械判定）**：**① 写入面 ＝ feicui-lite**（**上传路径上的格式转换点恰 1 处**；**本地侧对应物 ＝ feicui**）；**② 读取面 ＝ xiai-api**（**对外展示内容的唯一输出口**；**名称逐字 `xiai-api`**）；**③ 两面职责分开** —— **写入面只产**存储件**（face ＝ TIFF / scene ＝ AVIF）；**读取面只产**展示件**（WebP 切块 / 缩略图 / 下载件）**；**④ xiai-api 的消费面恰 2 个**（**xiai web 页面 ＋ yinsuo**；**同一套 api、同一份契约 —— 见 §3.24.5**）；**⑤ 本地 / 在线的定性不得互相冒充**（**feicui ＝ 本地运行；feicui-lite ＝ 在线运行**；**不得把「用 feicui 做批量素材」写成走 feicui-lite，也不得把「用户上传」写成走本地 feicui**）；**⑥ 不得据「出现了后端 / 服务 / api」判负**（**见 §3.24.6 ④ ＋ §10.22 表下注（v1.24 追加）②(b)**）。
- **判据落位**：**§10.22 AC-171**（两面归属与职责分开）＋ **AC-181**（双消费面）。

#### 3.24.2 写入面：上传路径与素材路径共用一套格式口径（face → TIFF、scene → AVIF）

- **⇒ 明文六条（可机械判定）**：**① 用户上传图片 ⇒ 经 feicui-lite 转换格式**（**不得绕开写入面直接把浏览器侧拿到的原字节当存储件落盘**）；**② face-photo 使用 TIFF**（**容器与变体口径仍 ＝ §3.22.1，原文一字未改**）；**③ scene-photo 使用 AVIF**（**scene 存储口径仍 ＝ §3.22.6，原文一字未改**）；**④ 管理员批量素材同样 face→tiff、scene→avif**（**「素材的格式同样也是」⇒ 两条路径共用一套格式口径；不得两套、不得按来源分流**）；**⑤ 单一真源** —— **格式归属（面类 ⇒ 容器）只有一处口径**（**即本节 ＋ §3.22.1 / §3.22.6；不得在写入面另立一份对照表**）；**⑥「尽可能都在前端」的适用面 ＝ 写入面，且只到能力允许处**（**见 §3.24.4**；**该句不构成「必须纯前端」的判据**）。
- **如实登记（形态，不作判据）**：**Kevin 原话的「上述部分不涉及到资源的防泄露」针对的是**写入面**（**上传 / 批量素材**）**；**读取面**的防泄露口径**另见 **§3.24.7 ③**（**两句话不是同一件事，不得混读**）。
- **判据落位**：**§10.22 AC-172**（格式口径单一真源）＋ **AC-173**（适用面与能力边界）。

#### 3.24.3 读取面：预览路径与直出路径（两条路径的职责切分）

- **⇒ 明文七条（可机械判定）**：**① 预览路径 ＝ 解 TIFF / AVIF → 转 WebP → 经 TileSplicer → 通过 api 输出给前端**（**四段职责顺序固定：解码 → WebP 转码 → 切分 → 输出**）；**② 直出路径 ＝ 缩略图 ＋ 「下载高清原图」⇒ 不经 TileSplicer、直接通过 api 输出**（**两段职责：转码 → 输出**）；**③ 两条路径不得互相冒充** —— **预览路径不得直出未切分的整图**（**面类源字节的整图不得作为预览产物**）；**直出路径不得夹带切块**；**④ 中间产物（WebP）是展示件、不是权威存储件**（**权威存储面见 §3.24.7 ①②；转码产物不得回写权威存储 —— 与 §10.21 AC-158 同族，该行原文一字未改**）；**⑤ 直出路径的产物 ＝ 全分辨率 WebP 0.92**（**下载件不得是 TIFF / AVIF 原字节 —— 与 §3.24.7 ③④ 同一句口径**）；**⑥ 预览路径的切块与直出路径的整图不得互换语义**（**缩略图不是切块、下载件不是切块集合**）；**⑦ 读取面不得对源字节做任何回写**（**读路径零副作用 —— 与 §10.21 AC-158 / AC-167 同族**）。
- **上屏文案（逐字）**：**Kevin 原话里的「下载高清原图」为叙述面用词**；**上屏面须满足繁体纪律（AC-72）⇒ 上屏**逐字**「下載高清原圖」**（**不得出现简体形态；判据见 AC-187**）。
- **判据落位**：**§10.22 AC-174**（预览路径）＋ **AC-175**（直出路径与下载）＋ **AC-180**（展示件形态与质量）。

#### 3.24.4 能力边界（**只写约束面，不写本工程的实现现状**）

- **⇒ 明文四条（可机械判定）**：**① 浏览器原生不具备 AVIF 编码能力** ⇒ **写入面的 AVIF 一段只能由服务侧承担**（**「尽可能都在前端」在 AVIF 面**不成立****；**不得违反该事实要求前端自编 AVIF**）；**② 浏览器原生不能解码 TIFF** ⇒ **读取面的 TIFF 一段须先转码为浏览器可直接解码的格式**（**与 §3.23.2 的转码职责同源，该节原文一字未改**）；**③ 上述两条的**来源**＝派单件转述的能力实测**（**本版不重跑、不声称、不写任何本工程的实现现状读数**；**也不得据「能力实测」要求实现侧改口径**）；**④ 不得据能力边界给「纯前端 / 必须后端」任一形态判对或判错** —— **判据只看职责归属与产物形态**（**§10.22 AC-173 / AC-179 / AC-180**）。
- **⇒ 明文（与名词面的关系）**：**本节的「AVIF / TIFF / WebP / Deflate」一类技术标识适用 §3.23.6 的「图像编解码面」命名例外**（**范围封闭；上屏面不适用 —— 该节原文一字未改**）。
