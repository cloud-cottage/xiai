# 规范增量 v1.122 —— 「批量掛圖」改按需檢索（新 op `searchBookImages` ＋ 行上 `image_count`）

- 作者：Zang（本轮破例）
- 提出：Kevin（2026-11-15）「『批量掛圖』改成按需检索」
- 主件状态：**未动** `docs/xiai.spec.md`（v1.117 / 794 条），由 Jing 合并；接 v1.121（`AC-811〜814`）

## 一 · 缺陷（判负）

旧「批量掛圖」面板在**前端**把全部印章/影像装配进浏览器（实测 6,445 張影像、6,033 枚章）
⇒ `/books` 首屏卡顿、主线程长时间被占（浏览器探针多次 5s 超时）。关联影像数亦由这份全量装配统计。

## 二 · 修法

### ① 新管理员只读 op `searchBookImages`（`ADMIN_OPS` **47 → 48**）

| 项 | 契约 |
|---|---|
| 载荷 | **封闭恰 2 键** `q`（必填，≤60 字）／`limit`（1〜100，默认 24）；未知键 ⇒ `INVALID_FIELD` |
| 语义 | 关键词对**印文 / 释文 / 章号 / 序号**做包含匹配，**简繁双形态**（复用 `authorMatch` 同一张 s2t 表） |
| 命中面 | 命中印章的影像行；**`EDGE`（边款）影像不入结果**（脸层口径：边款不属于可挂印面影像面） |
| 回包 | `{ok, rows, total}`：`total` ＝ 命中影像总数，`rows` 为**本页**（行投影**恰 5 键** `image_id/stamp_id/seal_name/kind/book_id`） |
| 门 | 第一行即管理员门；只读、**恒零写**；空 `q` ⇒ `MISSING_REQUIRED` ＋ **零读** |

### ② `listBooks` 行投影 11 → 12 键，新增 `image_count`

服务端一次读全 `xiai_images` 的 `book_id` 面并聚合，写入每行 `image_count`（整數，缺 ⇒ 0）；
计数面失败**不影响清单**（全部 0，不把故障伪装成「没有影像」）。

### ③ 前端

- 「批量掛圖」面板改为**检索式**：输入印文/章号 → 【檢索】→ 结果列表（每页 24 条）→ 勾选 → 挂上；
  未检索时明示「尚未檢索」，不再预载全量。
- 关联影像数改吃行上 `image_count` ＋ 本次页面内挂载增量（目标书 +1、原书 -1）。
- 面板头须明示：目标印谱下拉只列**当前页**，先用上方筛选缩小范围。
- 钩子：`data-books-image-search`；按钮 `data-action="book-batch-search"`（**不新增 `data-admin-action` 取值**）。

## 三 · 验收（`AC-815` 〜 `AC-819`）

| 编号 | 判据 |
|---|---|
| `AC-815` | `searchBookImages` 载荷恰 2 键；`q` 空 ⇒ `MISSING_REQUIRED` ＋ 零读；未知键 ⇒ `INVALID_FIELD` |
| `AC-816` | 按印文或章号均可命中该章影像；**`EDGE` 影像不出现在 `rows`**；行投影恰 5 键 |
| `AC-817` | `total` ＝ 命中总数（与 `limit` 无关）；无命中 ⇒ `total 0` 且 `ok:true`；全程零写 |
| `AC-818` | `listBooks` 行投影恰 12 键（含 `image_count`），`image_count` ＝ 该 `book_id` 的影像行数 |
| `AC-819` | `/books` 首屏**不再装配全量影像**（判负面：页面初始化即读全量印章/影像） |
