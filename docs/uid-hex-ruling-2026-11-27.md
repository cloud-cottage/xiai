# 裁定：用戶身份 uid 一律 hex 形（統一 `u-` ＋ sha256(手機號) 前 16 位）

- 狀態：**已裁定**（Kevin 2026-11-27 CST：「統一成 hex 形」＋同日「把 hex 形寫入 feicui 和 xiai 的備忘錄裡」）
- 性質：**跨倉硬口徑**。xiai 與 feicui 兩倉同文（各自 `docs/` 一份），供實現 / 質檢 / 運維作唯一口徑真源。
- 範圍：所有「用戶身份標識」的派生、落庫、查詢、上屏；**不含**業務鍵（書號 / 印面 id / 人物 id 等）。

## 一、口徑（逐字）

```
uid = 'u-' + sha256(<11 位手機號，純數字>) 的十六進制摘要前 16 位
      —— 全小寫；形如 u-91c5c051ff4eb59d
```

三條硬約束：

1. **永不用手機號明文當 uid**：`u-16601061656` 這類形態**一律不合規**，不得再寫入任何集合 / 令牌 / 日誌。
2. **單向不可反推**：uid 不可解回手機號（這是選 hex 而非明文的**唯一理由**：uid 會出現在上屏短碼、審核人欄、日誌裡，明文手機號即泄露源）。
3. **派生單點、同輸入同輸出**：前後端各有一份**同一算法**的實現，且必須逐字同值（機械自檢斷言）：
   - 前端 `src/data/uid.js::uidOf`
   - 雲函數 `cloudfunctions/xiai-user-token/lib/config.js::uidOf`
   - Web API `cloudfunctions/xiai-web-api/api/_lib/feicuiSession.js`（sha256 前 16 位）

## 三、遺留不合規數據（只讀容忍，禁止照抄）

| 位置 | 實際值 | 判讀 |
|---|---|---|
| `xiai_corrections.userId` / `user_id`（2026-10-03/04 舊行） | `u-16601061656` | **手機號明文形**，舊代碼產物；不得據此寫新行，也不得據此反推 uid 口徑 |
| `xiai_roles` `_id=role-2108059553674194945` | `uid: "2108059553674194945"`、`roles: ["ADMIN"]` | **平台數字 uid ＋ 舊數組鍵**；`roleFromRow` 認的是 `role` 單值（或已歸一的小寫數組），此形不可作樣板 |

處置原則：**不批量改寫歷史行**（改寫會動到審核留痕）；新寫入一律 hex，讀面遇到舊形按「認不出 ⇒ 當無角色」處理（fail-closed，不猜）。

## 四、讀面規則（兩倉共用）

1. **查角色 / 查身份一律按 uid 等值**（hex 形）；`where({uid})` 為主路。
2. **手機號只作橋接兜底**，且必須派生同源：
   - feicui 側 `cloudfunctions/feicui-shadow/lib/ops.js::loadRoleOf(db, uid, phone)`：平台數字 uid 查不到行時，按 `phone` 等值到 `xiai_roles` 認到同一個人（斐翠登錄是**平台賬號**，uid 是數字形，必須靠手機號過橋）。
   - xiai 側 `sessionAuthority::resolveSessionAuthority`：平台會話 uid 無行 ⇒ **兜底回落令牌路**（令牌 `sub` 是手機號 ⇒ `uidOf(sub)` ⇒ hex）。
3. **不得用客戶端自稱的 uid 判權**（`event` / `payload` 裡的身份類鍵一律拒）。

## 五、驗收判據（可機械判負）

- [ ] 全倉 grep `u-` ＋ 11 位數字 的拼接 / 字面量 ⇒ **零命中**（歷史數據不在代碼內）。
- [ ] `uidOf('16601061656') === 'u-91c5c051ff4eb59d'`、`uidOf('13784493933') === 'u-4813fa5c002d4568'`，前端與雲函數兩份實現**互等**。
- [ ] 新寫入的任何行，`userId` / `uid` / `reviewer_id` 欄位形如 `u-[0-9a-f]{16}`。
- [ ] 上屏短碼取 uid 前 6 位；**任何界面不得回退顯示手機號**充當身份。
