## 1. 概念定义（冻结）

- **印人（person）＝ 两支的并集**：
  - **A 支 ＝ 历史上的作者（已故）** ⇒ 落 **新集合 `xiai_persons`**；**新增成员须管理员审核**。
  - **B 支 ＝ 全站的用户** ⇒ **并入既有 `xiai_users` 集合**（Kevin 亲选），**不另建集合、不新增字段**；其显示名 ＝ 既有「昵称」、身份 ＝ 既有 `uid`（公开且不可反推手机号，沿 §3.49）。
- **明文（防误读）**：**两支属性面不同构** —— A 支有人物志属性（姓名 / 字 / 号 / 生卒 / CBDB·CARD id），B 支只有昵称与 `uid`。**不得用 `xiai_users` 去承载姓 / 名 / 字 / 号 / 生卒 / cbdb_id / card_id**（出现即判负）；也**不得因「两支并存」而要求给用户建 person 行**。
- **本期落地范围**：**只落 A 支**（`xiai_persons` ＋ `xiai_person_proposals`）；B 支零改动（沿用既有 users 形态）。

## 2. 集合 ① `xiai_persons` — 正式印人（历史作者）

| 字段 | 类型 / 值域 | 层级 / 权限 | 说明 |
| --- | --- | --- | --- |
| `id` | string（唯一） | 系统生成，只读 | 行主键 |
| `code` | `/^PR\d{9}$/`（`PR` 大写 ASCII ＋ 恰 9 位零填充） | 系统生成，只读，**任何写入口不得改 / 不得重排** | 印人编号（Kevin 亲选，与 `XA` / `SL` 同型） |
| `family_name` | string，可空 | 只经采纳路径写 | 姓 |
| `given_name` | string，可空 | 同上 | 名 |
| `courtesy_names[]` | string[]，可空 | 同上 | **字（多值）** |
| `art_names[]` | string[]，可空 | 同上 | **号（多值）** |
| `alias_names[]` | string[]，可空 | 同上 | 其它别名（CBDB `AliasType=未詳` 落这里，**不猜分类**） |
| `birth_year` / `death_year` | 整数，可空 | 同上 | 生卒年份（公元）。「不详」＝**空**，**不设特值、不设区间字符串** |
| `years_lived` | 整数，可空 | 同上 | 享年（预留字段位；本期不接线） |
| `birth_era_text` / `death_era_text` | string，可空 | 同上 | 年号原文快照（预留字段位；本期不接线） |
| `dynasty` / `gender` | string，可空 | 同上 | 预留字段位 |
| `cbdb_id` | string，可空 | **录入时手动填写**（Kevin 亲述）；本期零读取 | CBDB 人物 id（纯文本，**不做形态校验、不联网核验**） |
| `card_id` | string，可空 | 同上 | **CARD 接口 id；接口尚未接入**（见 §8 待裁 W-b） |
| `proposal_id` | string | 系统写，只读 | 溯源：产出本行的采纳提案 |
| `created_by` | string（`uid`） | 系统写，只读 | 采纳人（**非手机号**，沿 §3.49） |
| `created_at` / `updated_at` | ISO string | 系统写，只读 | 时间戳 |
| **（派生，不落盘）** `display_name` | — | — | 现场派生：`family_name + given_name` → 缺则 `courtesy_names[0]` → 缺则 `art_names[0]` → 皆空 ⇒ 空串（上屏一律回「佚名」）。**落第二份显示名 ⇒ 判负**（沿 §4.1.8 派生不落盘纪律） |

**索引**：`code` 唯一；`cbdb_id`（非空时）唯一；`display_name` 供检索。
**单写者**：本集合**只经采纳路径写入**；**不开放任何直写入口**（含管理员直写 ⇒ `FORBIDDEN` ＋ 零写入）。

## 3. 集合 ② `xiai_person_proposals` — 提案 / 审核行

| 字段 | 类型 / 值域 | 说明 |
| --- | --- | --- |
| `id` | string（唯一） | 行主键 |
| `batch_id` | string | 一次表单一批、N 条共享（沿 §3.44 口径） |
| `target_person_id` | string \| null | `null` ＝ 新增；非空 ＝ 修改既有（**修改的字段级粒度 ⇒ §8 待裁 W-f**） |
| `status` | `PENDING` / `ACCEPTED` / `REJECTED` | **三态单向、终态不回退**（沿 §7 / §3.47） |
| `family_name` `given_name` `courtesy_names[]` `art_names[]` `alias_names[]` `birth_year` `death_year` `cbdb_id` `card_id` | 同 §2 提交面 | 提案载荷 |
| `note` | string，选填 | 依据 |
| `submitted_by` | string（`uid`） | **提交人身份＝ `uid`；零手机号**（沿 §3.49） |
| `submitted_at` / `reviewed_at` / `reviewer_id` / `review_note` | — | 提交与审核留痕 |
| `dedupe_key` | string | 防重键：同 `(target_person_id, 姓名, 生卒, cbdb_id)` **只允许一人提交**；重复 ⇒ 结构化拒绝 ＋ 零写入（沿 §3.47.3 严格防重口径的形态） |

**状态机与权限（冻结）**
- 提交 ＝ **任何登录用户**（未登录 ⇒ 入口渲染、点击走登录引导；**不得 CSS 隐藏 / `disabled` 冒充**，沿 §3.47.7）。
- 采纳 / 驳回 ＝ **管理员**（登录令牌 ＋ 服务端手机号白名单，沿 §3.48）；**缺 env ⇒ 安全拒 ＋ 零写入**。
- `ACCEPTED` ⇒ **幂等生成 / 更新 `xiai_persons` 行**（`proposal_id` 溯源；重复采纳不改写既有行）。
- `REJECTED` ⇒ **零写入**。
- **审核载体 ＝ 复用「我的勘误记录」（`/my/corrections`）页的采纳 / 驳回形态**（Kevin 亲选）——**不新开路由、不新建管理员专区**（沿 §3.9 v1.3 收口：不做独立管理员页）。

## 4. 与印面 / 印章 / 勘误的关系（变体 B 强制引用）

### 4.1 印面「作者」＝ 引用型（`author_person_id`）
- **新增字段**：印面级 `author_person_id`（string，**可空**）。
- **选填（Kevin 亲选）**：**不填 ⇒ 空；填 ⇒ 必须从既有 `xiai_persons` 行中选择**（不得手输自由文本）。**不锁死上传**。
- **旧字段处置**：既有 `author`（自由文本）**保留不改写、不迁移、不清除**（Kevin「旧值不改写」原则）；自本模型起**降为历史回落**。
- **显示名链（单点，冻结）**：`author_person_id` → 命中 ⇒ `xiai_persons.display_name` → 未命中 ⇒ 旧 `author` 文本 → 皆空 ⇒「佚名」（与 §3.45 / `R-61` / `R-65` 的显示名链同型；**解析恰一处、零第二套名表**）。
- **印章行镜像**：印章行的 `author` 镜像**逐字保留**；**不在印章行新增引用副本**（避免双写漂移）——卡片 / 详情 / 导出一律经上面的单点派生取显示名。
- **引用值域门**：`author` 自本模型起**从「自由文本、不进值域门」变为「引用型、进值域门」**——判定在写之前（沿 §3.15.11「写前判定 ＋ 零写入」）；**reason 取既有字面值**（`INVALID_VALUE` / `NOT_FOUND`，沿 §3.12.10 / §3.25.10 冻结表），**不新增任何 `reason` 字面值**。
- **★ Zang 裁定（默认项，一句话可改）**：**本期「选人」选择器只检索 `xiai_persons`**（即历史作者）。理由：① D-2 明确用户不建行；② F1「必须从既有印人中选择」在冷启动前提下只有 A 支有可选行；③ 两支 id 形态不同（persons 内部主键 vs 用户 `uid`），混在一列会模糊值域。**若将来要让平台用户也可被选为作者 ⇒ 新增 `author_ref_kind`（值域 `person` / `user`）并把值域门扩为两源**（替代路径已写明，不必重推）。

### 4.2 勘误面「作者」
- **载荷改为「选人」**（Kevin 亲选）：不再接受自由文本；值域门判**引用合法性**（`author_person_id` 指向的印人存在）。
- **库中无此人 ⇒ 上屏引导去提交印人提案**（不是静默失败、不是放行自由文本）。
- `作者` 仍是 `MARKABLE_FIELDS` 的 7 项之一（**计数不变**）；但自本模型起其 `FIELD_VALUE_DOMAINS` **须登记为引用型**（现在「表里没有 ⇒ 自由文本一律放行」的旧读法对 `author` **不再成立**）。
- 防重 / 采信（§3.47）口径不变，只是「同值」在 `author` 上读作「同一 `author_person_id`」。

### 4.3 入口面（三处）
1. **上传印章弹窗**（既有「作者（選填）」输入框）⇒ 改为**检索 + 选人**控件；未选 ⇒ 空（合规）。
2. **勘误表单**（印章详情页）⇒ 「作者」字段改为**检索 + 选人**；无命中 ⇒ 出「提交印人提案」引导。
3. **「我的勘误记录」页**（管理员视角）⇒ 新增**印人提案的采纳 / 驳回**区块（复用既有按钮形态与二次确认链）。
