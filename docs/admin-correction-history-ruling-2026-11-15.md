# 裁定：管理员可查看自己审批过的全部勘误记录

- 状态：**已裁定**（Kevin 2026-11-15 CST：「页面可以看到我审批过的全部【勘误】的记录」）
- 性质：非规范。供实现 / 质检单作唯一口径真源。

## 一、口径

`/my/corrections` 页面，**管理员**要能看到**全部勘误记录**，包括**已经审批过的那些**（已採納 / 已駁回），不只待審。

## 二、现状（实测，2026-11-15）

| 面 | 现状 | 结论 |
|---|---|---|
| 云函数 `listPendingCorrectionsForAdmin` | 载荷 `{status?, limit?}`，**`status` 已支持 `PENDING` / `ACCEPTED` / `REJECTED`**，缺省 `PENDING` | **数据层已够用，不需新增 op** |
| 勘误行字段 | 已有 `reviewed_at` / `reviewer_id` | 可显示审核时间与审核人 |
| `src/services/corrections.js:1090` | 管理员列表**硬写 `status: PENDING`** | **真正的堵点** |
| 页面 `/my/corrections`（管理态） | 两个分页均显示「共 0 條」；只有待審面 | 审批过的记录无处可见 |

⇒ 这是**前端单点阻塞**，不是数据缺口。

## 三、实现契约

1. **服务层**：管理员列表函数增加 `status` 入参（默认 `PENDING`，取值只许三态），透传到既有门载荷；**既有调用点不传参 ⇒ 行为逐字不变**。
2. **页面**（`MyCorrectionsView.vue`，管理态）：
   - 新增页签：**待審** / **已採納** / **已駁回**（默认落「待審」，与现行为一致）；
   - 切页签 ⇒ 按对应 `status` 重新取数（每次上限 200，与 `CORRECTION_ROWS_LIMIT` 同值）；
   - 每行显示：印章/印面标识、字段、原值 → 新值、提交人、提交时间、**审核时间 ＋ 审核人**（已审行）；
   - 「已採納 / 已駁回」行**不出现**採納/駁回按钮（已终态）；待審行保持既有动作。
3. **可选（同批）**：「僅看我審的」开关 —— 前端按 `reviewer_id === 当前 uid` 过滤，默认关。
4. **普通用户面零变化**：只看得到自己的提交，页签不出现（管理员门控）。

## 四、硬约束

- **不新增 op**、不改 `ADMIN_OPS`（仍 47）、不改载荷/回包键名、零新增 `reason`。
- 不改状态机（`PENDING → ACCEPTED / REJECTED`）、不改采纳/驳回写路径。
- 卡片/列表 DTO 键面不变；上屏文案繁体（`s2t(x) === x`）。
- 管理员门控沿用既有判定（不得新增一套）。

## 五、验收

1. 管理员打开 `/my/corrections`：见三页签；切到「已採納」能列出已采纳记录（含审核时间与审核人），「已駁回」同理。
2. 待審页签行为与改前逐字一致（含 200 条上限与动作按钮）。
3. 普通用户：仍只见自己的提交，无新增页签。
4. 无新增 op / 无计数变化；既有 47 套套件全绿。
