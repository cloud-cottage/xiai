## 2. 编码（已穷举验证，0 失败）

- 字母表 **22 位**逐字：`A B C D E F G H J K M N P Q R S T V W X Y Z`（＝ Crockford base32 去掉数字后的字母子集；**不含 I L O U** ⇒ 与 0/1 天然不混淆）。
- **sid**：`n ∈ [1, 5153632]` ⇒ 定长 5 位 base-22，`1 → AAAAB`、`22 → AAABA`、`5153632 → ZZZZZ`。
- **fid**：`n ∈ [1, 100000000]` ⇒ 十进制 8 位零填充，`1 → 00000001`。
- **双向**：encode 为基数展开，decode 为基数累加 + 号域越界即拒。**双向均为纯函数、零表、O(1)**；`decode(encode(n)) === n` 已在 n = 1..5,153,632 全量验过。
- **容量悬崖（须规范登记）**：sid 上限 5,153,632（超限**结构化拒绝**，不得静默回绕）。升级路径 = 6 位（22⁶ = 113,623,104），**本轮不做**。
- **禁用派生**：**不得**由既有 `XA` + 9 位印章编号序号派生 sid（9 位容量 10⁹ 与 5.15M 差两个数量级）。

## 3. 字段面与号源

| 实体 | 新键 | 类型 / 值域 | 分配时机 |
| --- | --- | --- | --- |
| 印章 | `seal_no` | 整数 ≥ 1（自增号，权威） | 云函数发号（新建 / 导入采纳） |
| 印章 | `sid` | `/^[A-HJ-KM-NP-TV-Z]{5}$/`（恰 22 字母，实测展开 ＝ `ABCDEFGHJKMNPQRSTVWXYZ`） | **由 `seal_no` 重算，不独立分配** |
| 印面 | `face_no` | 整数 ≥ 1（自增号，权威） | 同上 |
| 印面 | `fid` | `/^\d{8}$/` | 由 `face_no` 重算 |

- **号源集合**：新增 `xiai_counters`（`_id` ∈ `seal` / `face`，文档含 `seq`），云函数内**原子自增**发号 ⇒ **集合清单 23 → 24 项**（须同步 §3.33.3 + `AC-293` + 各套件写死的计数断言，**期望值按严格等值亲改，禁删断言**）。
- **`xiai_counters` 不入云读面**：它是**服务端专用**集合（客户端零读），**不得加进 `CLOUD_COLLECTIONS` / `CLOUD_COLLECTION_KEYS` / `CLOUD_KEY_OF_LOCAL`**（加了等于把号源暴露给匿名读面）。可达性断言（`AC-522`）只覆盖云读面键，不受影响。
- **服务端重算校验**：载荷里的 `sid` / `fid` **一律不采信**；服务端按 `no` 重算后比对，不符 ⇒ 结构化拒绝、零写入。客户端可自算用于即时回显，但**落盘值恒由服务端产出**。
- **旧编号彻底退役（R-5 / R-6，V3 全量重编）**：印章 `stamp_id` 的值**改为 sid**（`"1"` / `XA000000001` 两种旧形态一律不再存在），`seal_no` 作权威整数序号、`sid` 由其重算。**旧 `XA…` 码与旧纯数字码一律不再受理**；旧深链 `/seal/1`、`/seal/XA000000001` **走「找不到」页，不做重定向**。
- **`faceId` 与 `imageId` 的内部形态不动**（派单方默认，一句话可改）：`faceId`（如 `fc-fx1-FACE`）、影像 `_id` 是**内部主键**，被勘误行的 `faceId` 引用；换掉会把 36 行勘误的 join 一起打断。**内部 id 不对外展示、不参与搜索**，对外印面标识只用 `fid`。新行由 `nextFaceId` 派生出的形态与旧行不同 ⇒ **登记为允许的形态并存，不得据此判负**。

## 5. 搜索面（R-4）

- 入口：广场页既有 `q` 关键词搜索之外**新增识别编码入口**（一个搜索框）。

## 6. 判据面（供规范侧参考边界，具体 AC 由 Jing 定）

1. 编码器**恰一处纯函数**，前端 / 云函数双副本**逐字相等**（机械断言，同 `MARKABLE_FIELDS` 纪律）。
2. 双射：`decode(encode(n)) === n` 对边界与抽样号成立；越界（0 / 5,153,633 / 10⁸）**结构化拒绝**。
3. 服务端重算：伪造 `sid` ⇒ 拒绝 + **零写入**；合法 ⇒ 落盘 `sid` ≡ 按 `seal_no` 重算值。
4. 并发发号：N 路并发新建 ⇒ **无重号、无空洞回填、`seq` 单调**。
5. 回填幂等：重放 `assigned: 0` ＋ 逐行前后快照逐字节不变。
6. **重编完整性**：`xiai_seals` 79 行 `stamp_id` 全部匹配 `/^[A-HJ-KM-NP-TV-Z]{5}$/`、两两不重复、`seal_no` 连续无空洞；**旧码（`"1"`…`"79"` 与任何 `XA…`）在五个集合里命中数 = 0**；勘误行 `sealId` 与新 `stamp_id` 的行数 join 一致（改前 36 → 改后仍 36，无孤儿行）。
7. 搜索判型：字母首字符 ⇒ 5 格；数字首字符 ⇒ 8 格；非法字符拒；查无 ⇒ 明确空态、零模糊回落。
8. 计数面：集合 24 项；`[data-admin-action]` 不新增；`reason` 字面值**零新增**（复用 `INVALID_VALUE` / `INVALID_FIELD` / `NOT_FOUND`）。

**三条关键事实（决定迁移规模）**

1. **云端从来没有 `XA` 字面值** —— `XA` + 9 位是**前端生成器**的产物，云端 79 行一直是纯数字 ⇒ **编号体系早已分裂两套**，本次重编同时收口。
2. **勘误的 join 键是 `sealId` 的纯数字值**（`"1"`），不是 XA 值 ⇒ 重编必须**同批**改勘误两处（私有行 + 公开投影），否则采纳结果与印章断链。
3. **真正要改的是约 280 行**（79＋79＋80＋36＋6），不是 3,781 —— 导入行在采纳时才发号。

**迁移顺序（不可逆，逐步可停）**

1. **备份**：`db nosql dump` 落四集合到 scratch（不入仓），记 md5 与行数。
2. **干跑**：`migrateCodeNumbers` `dry_run:true` ⇒ 出**完整映射表**（`old_stamp_id → (seal_no, sid)` 共 79 行 ＋ 印面 79 行），人工核「无重号、无空号、sid 形态全匹配」后再放行。
3. **写**：先 `xiai_seals`（分配 `seal_no` / 写 `stamp_id = sid`）→ 再 `xiai_faces` / `xiai_images`（跟新值）→ 最后 `xiai_corrections` / `xiai_corrections_public`（跟 `sealId`）。
4. **回读**：四集合各取 count ＋ 抽样 `find` ＋ **逐字段前后快照**；旧码命中数必须为 **0**。
5. **回滚清单**：备份文件 ＋ 反向映射表（新值 ← 旧值）——**映射表落 scratch、不入仓**（含生产 id）。

**执行权**：生产写入由**人类逐项确认后由派单方执行**；子代理只做代码与离线自检。**本件只登记口径与清单，不含「已迁移」结论。**

**8.6 连带迁移面（本地引用，须同批处置）**：`/s/<code>` 分享页与「我的雲盤」的引用行（`seallist-items.seal_id`）投影里带 **`seal_ids` ＋ `sealBriefOf(seal_id)`**（`src/services/drive.js` 实测）⇒ 旧引用值在重编后变孤儿（破图 / 找不到），**不迁移会让已发出的分享链静默半坏**。

- **映射是纯函数、不需映射表**：发号顺序＝旧号数值升序 ⇒ `旧 "N"`（或 `XA0000000N`）→ `seal_no = N` → `sid = encodeSealCode(N)`。本地引用一律**就地重算纠正**（bootstrap 阶段，读到旧形态即换算），**不得清库、不得换命名空间**。
