## 1. 文档约定

### 1.1 与其他文档的关系（三份规范 + 一份端口真源）

| 文档 | 管什么 | 本文件如何引用 |

| `xiai/docs/yinsuo-web.spec.md` | **印索** Web 展示站与控制台 | **只读引用**（目录改名后的现行路径；本文件不改该文件一个字节） |

| **`ctrl/PORTS.md`** | **全 bistro 端口数值的唯一真源**（运行时真源＝`ctrl/index.js` 的 `services` 表） | 端口数值**一律以它为准**；玺爱端口 **5163** 已由 Jing 在 `PORTS.md` 登记（见 §12 变更记录） |

**边界纪律**：玺爱是**产品与数据归宿**（Zang 裁定 R-7：以后斐萃的数据均存入玺爱的数据库 ⇒ 玺爱是数据归宿、斐萃是入库管线）；本文件**不约束**印索与斐萃的内部实现形态，只约束玺爱侧如何消费这些数据。

### 1.2 现状读数纪律（跨文件同源）

1. **凡需证明「数据未变」的现状读数与红线判据，一律用内容指纹，禁用数据库文件 md5**——库处于 WAL 时，`yinpu.db` 的**文件** md5 会在**内容无任何变化**的情况下漂移，而同刻内容口径逐字节未变。**判负形态**：① 以「库文件 md5 不等」判「数据被改」；② 要求复检者提交**库文件 md5** 作为通过判据；③ 用 `sqlite3` CLI + md5 在 WAL 库上取数（得空输入的假结论）。本条与 `ctrl/PORTS.md` 制度 (f)、`xiai/feicui/docs/feicui.spec.md`、`xiai/docs/yinsuo-web.spec.md` **同源**。
2. **「现状 / 事实」类段落必须以磁盘实测或可复算命令输出为准**，并**标注核验时点与证据来源**；**不得从派单 / 聊天 / 口述转述照抄**。派单与磁盘事实不一致时**以磁盘事实为准**，差异登记入本文件的报告与 §11。
3. **未实测的项一律如实标注「未实测」**，不得以推断冒充实测（伪造成功＝红线）。

### 1.3 变更流程（含第 0 步快照、两处版本记录同步、判据纪律）

0. **第 0 步 · 改版前先快照**：在改动本文件**之前**，先把当前版本**完整复制**为 `xiai/docs/versions/xiai.spec.v<主文件当前版本>.md`（例：改 v1.0 → 先存 `xiai/docs/versions/xiai.spec.v1.0.md`），**再改主文件**；快照文件是**字节级回溯的唯一依据**。
1. 提出变更（Zang 派单 / Kevin 口径）→ 2. 若属未决，先登记 §11 待裁项 → 3. **Kevin 确认**（或 Zang 依 Kevin 已答口径裁定）→ 4. 本文件升版本号 → 5. 同步受影响 AC 与路由 / 权限 / 积分条款。
6. **两处版本记录同步**：每次改版**必须同步更新两处**——**① 表头「最近修订」块**（补当版一行，内容按 §12 该版条目摘要、**不得虚构**）与 **② §12 变更记录表**（新增当版一行）；**任一处漏写即视为改版不完整**。
7. **判据纪律 · 跨层契约缝必须有端到端用例兜底**：凡「**页面筛选 / 参数变化 → 数据集变化**」的路径，除单元级断言外，**必须有端到端用例**验证「**选项改变时返回集合真的跟着变**」，**不得只验单层**。**判定方式**＝检查测试 / 留档用例中是否存在**从页面侧入参出发、经 services 契约缝、回到返回集合**的断言，且断言**集合内容随选项改变而改变**；**只断言「调用未报错 / 返回非空 / 单层入参正确」不算端到端**，**单层断言全绿不构成通过证据**。**实证反例**（同工作台既有教训 D1）：**页面传 `range`、适配层只认 `from/to`**，在 121 条单层断言全绿的条件下漏网。本条由 **AC-17 / AC-18** 承载。
8. **口径数值唯一性**：端口、积分、初始余额等数值只在本文件写一处，其余位置引用；**端口数值以 `ctrl/PORTS.md` 为准**。

## 3. 已冻结口径（Kevin 已裁定 / Zang 已转述，逐条写入）

### 3.1 工程与端口（R-4 / R-5）

- 工程根＝**`/Users/kevin/bistro/xiai`**（Vite 工程根，入口 `index.html`）；与 `xiai/web`（印索前端）、`xiai/feicui/`（斐萃）并列。
- 端口＝**5163**；**`server` 与 `preview` 均 `strictPort: true`**；**保留端口 5173 / 5174 不得使用**（既不得占用，也不得作为回退目标）。
- 端口数值的唯一真源是 `ctrl/PORTS.md`（玺爱行已登记）。

### 3.2 数据层（R-1）

- 数据层＝**纯前端 mock + services 抽象层**（种子数据 + `localStorage` 持久化，**零后端、零外部请求**）；**数据访问统一经 services 层**，页面 / 组件不得直接读写 `localStorage` 或种子数据。
- **后续可整体换真实后端**（services 层是唯一替换面，页面零改动）。

### 3.3 登录（R-3）

- 登录＝**手机号 + 验证码**；**开发登录约定沿用本工作台既有口径：验证码固定 `1234`**。

### 3.4 积分（R-2）

- 新用户初始 **50 金**；下载高清印面消耗 **5 金**；勘误被采纳奖励 **10 金**。
- **下载计费维度＝印章**（见 §2.1 原文 1）⇒ **同一印章同一「下载会话」内重复点击不得二次扣费（幂等）**；**余额不足须拦截并给可读提示**。
- **流水字段至少含**：金额（带符号）/ 类型（下载消耗、勘误奖励、初始赠送）/ 时间 / 关联对象 / 变更后余额。

### 3.5 数据模型对齐（R-7）

- 数据模型**对齐斐萃 `yinpu.db`**；**以后斐萃的数据均存入玺爱的数据库 ⇒ 玺爱是数据归宿，斐萃是入库管线**。
- 层级：**印章 1 对 N 印面**；**边款是一种特殊印面**。
- 印面记录字段命名对齐斐萃 **`seals`** 表（涉及表：`stamps` / `seals` / `images` / `export_batches` / `export_records` / `jobs`）；印面影像对齐 **`images`** 表（`kind` 取值 **FACE** 或 **EDGE**，另带 **`sha256` / `bytes` / `width` / `height` / `color_mode`**）。

### 3.6 三类属性

| 类别 | 内容 | 权限 |
| --- | --- | --- |
| **固定属性** | 印面图片（`images.kind = FACE`）、**材质**（`material`）、**边款图片 ID**（`images.kind = EDGE` 的行 id） | **仅管理员可改**；**普通用户不可见编辑入口**，且**数据层须拒绝越权写** |
| **可标记属性** | 印文简体字、印文古字、朝代、分类、作者、印文释义 | 普通用户**可提交勘误**，**不直接覆盖原始数据** |
| **影像属性** | 用户上传的印章实物照片 | 登录普通用户可上传（玺爱自有，斐萃无） |

### 3.7 权限矩阵（逐字）

| 能力 | 游客 | 普通用户 | 管理员 |
| --- | --- | --- | --- |
| 浏览印章 / 印面 | ✓ | ✓ | ✓ |

| 下载高清图并扣金 | ✗ | ✓ | ✓ |

### 3.8 勘误状态机（逐字）

`待审核 PENDING` / `已采纳 ACCEPTED` / `驳回 REJECTED`。**提交不覆盖原始数据**；**同一字段多条勘误由平台按「可信度」汇总后对外展示**；**采纳每条只奖一次 10 金**。
**新增条款（需求原文未写，Zang 裁定）**：管理员专区须含**「勘误审核」**页签——因「审核通过后奖励积分」必须有审核点。
