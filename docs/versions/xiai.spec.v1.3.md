### 5.2 下载计费维度＝**印章**（需求原文，逐字）

> 「同一枚印章，无论下载多少印面，只算作 1 次下载，本次下载消耗指定数量积分」（§2.1 原文 1）

派生口径：

1. **计费单位是印章，不是印面**：同一枚印章的多个印面，**一次「下载会话」内合计只扣 5 金一次**。
2. **幂等**：**同一印章、同一「下载会话」内的重复点击不得二次扣费**——重复点击**要么被判定为同一会话（不再扣费），要么明确提示已扣费 / 已下载**；**不得**每次点击各扣一笔。
3. **「下载会话」的边界由实现侧定义并写入 README**（本文件只定「同会话幂等」这一判据，见 §10 对应 AC）；**跨会话是否再计费不在本版冻结范围**（如需冻结，走 §1 变更流程）。
4. **流水条数**：一次成功下载**只产生一笔** `下载消耗` 流水（金额 `-5`）；**同一会话的重复点击不得新增流水**。

### 5.3 余额不足拦截

- **拦截点**：余额 < 所需金额时，**数据层（services）必须先拦截**——**不得**先扣成负数再回滚、**不得**以「下载失败但已扣费」收场。
- **用户可见反馈**：给**可读提示**（说明所需金额与当前余额），**不得**只抛技术错误码 / 静默失败。
- **副作用为零**：被拦截的下载**不产生流水**、**不改余额**、**不记下载次数**。
- **判负形态**：拦截缺失（余额被扣成负数）；拦截在数据层缺位（仅 UI 层禁用按钮即为缺位——**UI 禁用不能替代数据层拦截**）；拦截后仍写入流水 / 仍改动余额。

### 5.4 积分流水（`ledger`）口径

- **字段**：见 §4.1.6；**金额带符号**（消耗为负、奖励与赠送为正）、**类型枚举只三类**（`下载消耗` / `勘误奖励` / `初始赠送`）、**每笔必带「变更后余额」**。
- **可复算**：任意时点的余额应能由「初始 50 + 全部流水金额」逐笔复算得到；**「变更后余额」与复算结果不一致即判负**。

## 7. 勘误状态机

### 7.1 三态（冻结）

| 状态 | 取值 | 说明 |
| --- | --- | --- |
| 待审核 | `PENDING` | 提交后的初始态 |
